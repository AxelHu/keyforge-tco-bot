## 0.6.2 的生命周期估值

全部 **89 个策略 ID** 与 **5 项常用菜单**保留，默认仍为 Engine V3。本轮改变共享评分路径中的区域转移与再次使用机会估计；策略实现仍由包版本和源码提交区分，同名 ID 不表示行为跨版本完全相同。

已支持的转移按 `V(实际目的地) − V(原区域)` 比较，整次候选动作再统一结算一次正常补牌差分。普通牌质量复用公开效果估值与已有回退；当前能否正常打出、是否占用补牌、是否只能等待后续档案取回或再循环分别处理。时间折价与普通效用仍是启发式，没有完整牌组组合搜索。

本轮修复的具体边界包括：

- **回收与窗口**：识别可明确证实的单一 Reap 回收后正常出牌机会；第三钥匙紧急优先级仍须通过当前屋、费用、容量、六次规则、禁用、Omega 和父续段等门控。回到手中不等于已经出牌或铸钥匙。
- **归档与补牌**：区分当前可用手牌、非当前屋手牌和弃牌堆归档；多张移动按整次候选结算补牌，回合结束已补手后的归档不再领取当前补牌位。
- **目的地与绑定**：外来档案离开时按实际替代回所有者手牌；替代后的清除不支付成功清除续段。已支持的组合绑定按物理身份去重，未知持有者或多部件目的地保留不确定性。
- **Scrap 与来源**：只对真实当前玩家手牌弃置评估已支持的 Scrap；整批先移动，再执行子效果。子帧保留父 Play 已离手、已入场和当前回合计数，结束后恢复父来源。
- **保留范围**：普通 destroy、sacrifice 与战斗致死继续使用既有破坏估值，本轮未为这些路径统一叠加弃牌堆未来机会。

改动前的冻结 0.6.1 诊断完成 **32 局**，记录 **6,564 个决策快照、52,046 个各类合法候选**。其中精确识别的 **25 个非在场归档提示／415 个目标候选**出现全部零分；Tick-Tock 的 11 个可选提示均选 Done。这证明指定消费者缺少目标区分，不能直接当作 25 次错误、415 次独立机会或“每次都应该归档”。受控 Witch 第三钥匙获胜路径和 Labwork 窗口验证另列，公开输入重放不新增整局，也不计入确认样本。

源码 `ead3992` 的完整离线回归为 **549／549**，由原有 483 项加本轮 **66 项**组成：区域模型 28、严格回收窗口 19、消费者整合 19。专项通过说明相应输入下的行为，不证明所有生命周期交互均已支持。

固定对照设计为同一组 12 副公开牌组上的 **96 局开发 + 384 局确认**，对冻结 0.6.1 比较 **Engine V3 与 Card Effects V3 各自的新旧实现**，并交叉平衡候选席位和先后手。确认使用预留新对局种子；牌组集合仍已知。沿共享 Card Aware V3 路径运行且未禁用新分支的派生调用可以继承改动，比较范围仍只有两个家族，不能外推为常用五项或全部 89 个 ID 的性能验收。

方法、最终结果和限制见[生命周期估值报告](card-lifecycle-evaluation.md)及[公开证据摘要](evidence/card-lifecycle-2026-11-18.json)。局部估值修复不能直接推出稳定胜率提高，也不改写下方历史 Elo；本轮没有新增线上战绩。

## 0.6.1 的历史动态公式更新

五项常用菜单和全部 89 个策略 ID 保留。0.6.1 更新共享数量估值，并比较 Engine V3、Card Effects V3 各自的新旧实现，没有重评全部策略。对 0.6.0 的确认集主要估计为 201 胜 183 负（52.34%），单独对 0.5.3 参照为 102 胜 90 负（53.12%）。请结合[分策略结果及条件性区间](contextual-formula-evaluation.md)判断，不将它们填入历史 Elo 表。

已支持的动态公式按当前公开场面求值；随机量只使用有依据的公开分布。缺事件／历史／绑定上下文的部分继续保留不确定性。最终候选修正了 captured 和 haunted 的连续状态依赖；前两候选结果另记。国际服真人匹配仍暂停，该版本没有新增服务器实战验收。

## 0.6.0 的历史实现与单独对照

0.6.0 保持上述 89 个 ID 与 5 项常用菜单，通过包版本和源码提交区分实现。共享评分分支已迁移到结构化卡牌能力与当前决策语义；同一个策略 ID 不保证跨包版本动作完全一致。

本包保留原项目注册的 **89 个代码策略 ID**，注册集合与顺序均与提取来源一致。它们包含通用策略、专项规划、旧版本、实验候选和随机/探索基线；**完整保留不等于把 89 个策略并列推荐**。算法实现没有因菜单分层而删除。

默认策略仍是 **Engine V3（`tactical-style-engine-v3`）**。常用菜单先列默认项，再列四个可比较的候选；历史 Elo 表则独立按分数排序。菜单默认项不代表历史榜首。

## 查看和选择

```sh
# 常用的 5 个策略
node bin/kf-auto.mjs strategies list

# 全部 89 个注册策略，包含专项、实验及历史版本
node bin/kf-auto.mjs strategies list --all

# 查看某个精确 ID 的说明
node bin/kf-auto.mjs strategies show tactical-style-engine-v3

# 供脚本读取；--all 可与 --json 一起使用
node bin/kf-auto.mjs strategies list --json
node bin/kf-auto.mjs strategies list --all --json
```

这些选单命令在本地读取策略元数据，不连接服务器、不打开浏览器，也不修改已有配置。列表展示不需要运行策略或开始对局。所有策略 ID 都保持稳定，不能只凭标签或版本数字推断强弱。

初始化时可以显式指定策略：

```sh
node bin/kf-auto.mjs init \
  --directory "$PWD/.local/my-bot" \
  --origin 'https://your-keyteki.example' \
  --account 'YourAccount' \
  --server-deck-id 12345 \
  --deck-name 'Your deck name' \
  --policy tactical-style-engine-v3
```

也可以将最后一项换为 `--choose-policy`，在交互终端按编号选择。`--choose-policy` 仅支持 TTY，不能与 `--policy` 同时使用；脚本或管道环境请显式传入 `--policy ID`。初始化在选好有效策略并通过配置校验后，才创建新的配置文件。两者都不指定时，使用 Engine V3。

尚未启动的席位配置也可以直接修改 `self.codePolicy`，然后重新预检查。全部 89 个注册 ID 都仍可使用，未注册的 ID 会在配置校验阶段拒绝。`campaign prepare` 会把当时的席位配置复制进新连续对局配置；以后修改原 `seat.json` 不会自动改变已经准备好的 campaign。**已经开始的 campaign 不要热改策略**：它绑定配置摘要和已有记录。需要换策略时，使用新的配置与输出目录准备另一个 campaign，并保留既有未解决状态。

下表按菜单顺序排列，说明它们侧重什么。具体表现仍取决于牌组、对手和实际局面；这些都是当前观察上的启发式评估。

| 菜单项 | 精确策略 ID | 主要侧重 | 使用时要知道 |
| --- | --- | --- | --- |
| **场面引擎 V3（默认）** | `tactical-style-engine-v3` | 部署永久物，并兑现当前可用的场面能力与资源；包含公开防守和资源风险修正。 | 默认便于延续现有配置，不是历史 Elo 最高项；不进行完整对局搜索。 |

### 完整列表中的专项、实验与历史项

`strategies list --all` 保留全部入口，`strategies show ID` 可查看单项说明：

- **专项规划**包括 Tullibint、Prophecy、Season，以及 Token/锁等细分方向。先确认牌组和机制是否符合其适用范围，再与通用策略比较。
- **历史和对照**包括旧版风格策略、Ladder 系列、基础策略及其他版本。`tactical-ladder-balanced-v2` 仍可通过完整列表和精确 ID 使用；它未列入常用五项，算法没有被删除。
- **实验和高级扩展**包括随机/探索基线和需要额外上下文的入口。DOK 系列可接收调用方显式注入的缓存；普通 CLI 选中其 ID 不会自动下载外部评分数据，缺少缓存会走既有 `missing-cache` 路径。

专项适配、实验身份或历史版本标签不是新的性能结论。策略元数据与算法注册分开，菜单不会改变动作合法性、控制权或发送保护。

## 选好策略后能直接启动吗

公开仓包含独立运行所需的策略、静态知识、桥接与后台工具。完成 Linux 环境、Node/Python/Chromium、依赖、构建及本地配置后，可以使用[操作指南](operations.md)中的单席或连续对局命令，不需要原私有 KF 引擎或 OpenClaw。

目标站点仍需兼容当前支持的 UI。现有流程使用 `/login` 和 `/api/account/login`，按 `Select deck`、`Select row <serverDeckId>` 选牌，并使用“新游戏”“开始”等中文房间按钮。这是具体的中英混合界面绑定，不能仅凭改好 origin 就认定任意 Keyteki/TCO 前端已经兼容。**当前公开 TCO 的完整无人值守流程尚未端到端实战验证。**

`preflight` 核对本地配置和文件，不读取密码、不登录、不认证当前 UI。未知原生机制或无法确认的身份仍会保留原有停止/暂停行为；选择另一个策略不会绕过这些条件。
