# 卡牌知识与策略范围

本包根据玩家观察选择动作。远端 Keyteki 兼容服务器提供合法菜单，并结算真实卡牌效果。本包保留策略所需的静态卡牌知识，不包含 Game 构造器、权威状态推进函数、隐藏牌序、重放执行器、规则调度器或可运行的复刻卡牌模块。

## 默认保留哪些知识

默认知识包恢复**原目录中全部 2,546 份完整静态卡牌定义**，合计涉及 **194 种根字段**，包括原有 `summary` 说明和 `ruleInterpretations` 解释标注。卡名、印刷数值、阵营、类型、力量、护甲、琥珀、特性、关键词，以及定义中其他静态规则字段一并保留；这不是对所有已发行卡牌的完整覆盖声明。卡牌知识可以描述规则，实际合法性和结算仍以远端服务器为准。

恢复后的默认目录没有删去原字段或效果节点，没有生成的人工 unknown 标记，也没有默认 `summaryFeatures`。原目录中的 **2 份研究约定（research-convention）**原样保留。数据是纯静态结构，并保留原有属性存在性：Chronometer 的 `filter.kind` 有 **1 处显式 `undefined`**，它与属性缺失不同，不能经过普通 JSON 往返后丢失。

策略数据中的卡名、卡文和解释标注保留原语言，中文化只作用于项目说明。ToC/WoE 来源原文单独放在 `src/knowledge/printed-text.ts`，共 **107 条非空原文和 1 个必要空值**；对应来源记录绑定仓库、提交、URL、原始文件 SHA256 和每条文本的 SHA256。另有 3 条 WoE 自有 fallback 说明保留在内置定义中，不计入这些第三方非空原文。第三方文字的来源和许可不能笼统归入本项目原创代码的 MIT 声明，具体见 [NOTICE](../NOTICE.md)。

用于体积比较的完整定义紧凑 JSON 序列化为 **1,257,878 字节**；首次发布的有限投影为 **1,095,139 字节**，差额为 **162,739 字节**。这只是序列化体积指标，不能表达前述显式 `undefined` 的属性存在性，也不代表源码、编译输出、依赖或冻结运行时的总占用。实际静态定义保留该属性。恢复这些知识不需要引入 Game、服务器或完整可执行规则闭包。

## 完整数据与有限估值分别看待

包中保留 `tactical-style-engine-v3` 及其已注册代码策略系列，对观察中已经出现的动作排序。Unity Prism、Sir Jaune、They Tell No Tales、Infurnace、公开摧毁/琥珀返还、阵营防守和可用工作排序等，仍属于策略计算。预计资源变化不是实际结算，也不能证明未来动作一定合法。

数据类型、能力分类与数值估值分别统计。当前 0.6.1 的范围与 0.6.0 的历史范围如下：

| 口径 | 数量 | 实际表示 |
| --- | --- | --- |
| 完整静态规则数据，0.6.1 保持不变 | **267 种 effect kind** | 默认卡牌定义实际保存的效果节点种类，包含估值器尚未完整解释的节点。 |
| 0.6.1 强类型估值合同 | **51 个标签，默认数据命中其中 50 种** | 类型接口新增 `randomCard`、`bindRandom`、`randomDeckTop`、`withValue` 四种真实规则形状；`finishAction` 不在默认静态库中，显式 `unmodeled` 扩展另计。 |
| 0.6.1 只读未解释静态节点 | **217 种** | 在完整静态库中保留，但没有进入上述强类型估值标签范围。类型声明、数据保留与完整行为模拟不是同一件事。 |
| 0.6.1 结构化能力分类 | **44 种节点** | `semantic-features.ts` 显式处理的节点种类，用于提取能力潜力；另有部分静态根字段判断。 |
| 0.6.0 历史强类型标签 | **47 个标签，默认数据命中其中 46 种** | 当时另有 221 种静态节点保留为未解释数据；该数字属于旧版本。 |
| 0.6.0 历史能力分类 | **40 种节点** | 0.6.0 首次结构化分类的处理范围，不作为当前数量。 |

44 种节点是能力分类器的范围，不能据此宣称完成 44 种规则的完整数值估值，也不能用它与 51 个类型标签相减来计算新增支持量。当前的 `50 + 217 = 267` 描述静态库在类型接口中的分类，不能解释成完整规则交互支持率。四个新增类型也都有数量、可见性和续段限制。

结构化分类器读取 effect 节点、触发时机、己方/敌方、选择绑定与静态字段，不依赖 `summary` 中出现的词或 `summaryFeatures` 掩码。它同时报告 `conditional`、`unknown`、`unknownKinds` 和 `unknownFields`。无观察上下文的静态分类可以保留结构上可能发生的条件能力，同时将数量留为未知；有公开上下文时，再根据当前场面判断哪些数量和条件已经确定。

0.6.0 的数量型能力标志曾把公式对象作为未知处理，但其动作数值估值器已经独立计算了一部分公式。因此，看到某个 `unknown` 并不能推断整张牌被估值为零。0.6.1 将公开求值结果接入能力消费者和实际动作排序，修补可计算数量与能力标志之间的缺口；这仍不等于所有动态规则都能被完整预测。

类型定义不会引入引擎的 Frame、PendingChoice 或结算执行器。`CardDefinition` 是静态知识接口的兼容名称，`ALL_DEFINITIONS` 和 `registerCardKnowledge()` 保持原有接口；这些接口不代表本包能够执行完整对局。

“知道这张牌是谁”“保留其完整静态定义”“能够估计部分效果”“在特定场景验证了策略行为”是不同的结论。未知或不支持的效果不能因为字段已保留，就被当作已理解的确定性零影响。公开状态、当前可用动作和估计中的不确定性仍是策略判断的边界。

这里的 `unknown` 不表示该牌无法运行。游戏规则仍由远端服务器或独立测试裁判执行；只要合法动作与命令绑定已经建立，策略仍可结合已知印刷数值、其他结构化能力和通用回退作出选择。卡牌身份未映射、原生提示无法绑定等适配问题属于另外的状态，不能与某个能力特征尚未被分类混为一谈。

`cardKnowledgeIsPartial()` 会报告显式 `unmodeled`，以及 `status: "research-convention"` 且 `officialRulingConfirmed: false` 的知识情况。这个标志不认证全部效果都能被估值；原研究约定也不会因恢复完整数据而自动变成官方裁定。

`src/contracts/observation.ts` 定义玩家视角和决策数据。`src/shared/canonical.ts` 提供从原重放执行器分离出的纯稳定序列化函数；显式 `undefined` 仍会影响其哈希结果。静态知识的具体类型和数据位于 `src/knowledge`。

## 0.6.1 的公式与随机估值边界

`evaluatePublicValue()`、`evaluatePublicCondition()` 和 `selectPublicCards()` 只接受玩家观察、可见物理来源、公开选择绑定和明确的局部投影。当前公开场面可确定的数量，应直接求值；隐藏身份、未公开事件量或缺失的历史计数则不能补成精确零。上下文结果与静态定义缓存分开，同一张牌的能力和数量会随场面变化。

返回值区分 `exact`、`expected`、`interval` 和 `unknown`。`expected` 必须有显式概率模型；只有上下界时保留区间，不自动取中点。数值策略以确定数量处理相应的比较与循环。随机候选完整可见时，先逐个计算结果内的资源上限和条件效用，再平均；均值不被重新当作一个确定的游戏状态。当前随机绑定续段的候选枚举上限是 32。

序列计算保留当前资源池、手牌和档案数量、已知区域变化及临时绑定作用域，避免重复统计正在打出的来源、两张巨大生物组件或已经花费的资源。共同确定的随机后状态仍可使用；分歧状态不能从旧观察中恢复成假精确值。明确成功的准备、横置和眩晕可以继续进入计数，未可靠投影的伤害或力量变化则保留具体原因。

随机弃牌默认作用于自己，并读取指定的手牌、档案或弃牌区域；实际数量必须封顶。对公开样本计算的是既有估值函数下的效用期望，并非已证明的获胜概率。对手隐藏牌面没有凭空生成的分布，Scrap 与弃牌响应可能改变后续取样；存在这些依赖时，只保留已注明假设的直接操作估计或未知续段。随机铸钥和跨分支费用变化尚不能由均值认证。回顶类效果中，`randomDeckTop` 移动全部匹配且仍在场的目标，只有顺序随机。

这些边界属于策略预测，与完整静态规则数据继续保留、远端规则照常执行并不矛盾。详细方法与限制见[公开公式与随机估值](contextual-formula-evaluation.md)，对应数据见[脱敏证据](evidence/contextual-formulas-2026-11-17.json)。

## 卡文保留与结构化策略

真实的 `summary`、已有的 `ruleInterpretations`、印刷卡文及全部静态规则数据继续保留。原先为替代卡文而生成的 `summaryFeatures` 掩码和人工投影标记不作为默认知识内容，新的结构化能力分类也不读取该掩码。

从 0.6.0 起，代码策略中原先依赖 `summary` 关键词的能力判断已经迁移到 `cardSemanticFeatures()`。当前选择步骤则消费 `pending.intent`、实际选项的 `house`、准确来源及可选的公开续段位置；源卡名称或显示标签不能替代当前步骤的结构化证据。外服协议仍有少量缺少机器类型的提示和日志，其有限文字兼容集中在适配层维护，具体职责见[架构](architecture.md)。

卡文仍供展示、说明和可选模型输入使用，例如 JEV 输入保留规则说明。模型消费者与结构化代码策略使用的字段和行为需要分别验证；代码策略的文案替换回归不能自动证明模型输出也完全不变。卡文、规则描述和解释标注作为数据保留，不会新增本地结算执行器。

0.6.0 的迁移范围、当前续段绑定与未知处理见[结构化策略语义](structured-strategy-semantics.md)。

## 扩展知识包

`registerCardKnowledge(entries)` 用于在会话开始前注册额外静态知识。条目需要通过静态数据结构、深度限制和字段校验。重复或无效知识包会在安装任何条目前整体拒绝，不能静默覆盖内置身份。定义会被复制并冻结；适配器解析卡名时读取当前目录。

扩展接口仍是策略数据接口。加入静态规则知识不等于加入隐藏物理牌身份、账号数据或本地对局执行器。对于未支持的规则和不确定观察，调用方应保留这种区别，不能用已知零效果代替未知情况。

## 验证与棋力说明

公开测试使用手工构造的协议/观察夹具，直接调用真实适配器、策略和控制器，不启动本地 Game 或连接服务器。**0.2.0 的历史验证**包括严格编译、185 项回归，以及全 2,546 份定义与 30,552 项文本谓词的独立差分检查，结果绑定当时被验证的源码输入；这些文本谓词检查保留其历史归属，不作为后续结构化语义覆盖或当前棋力的证明。各版本实际检查见[验证记录](validation.md)；0.6.0 的迁移见[结构化策略语义](structured-strategy-semantics.md)，0.6.1 的数量求值见[公开公式与随机估值](contextual-formula-evaluation.md)。

历史 17 胜 3 负的自然对局结果属于原冻结运行时。独立包有自己的打包、部署配置和版本身份；没有新增实战战绩，就不能给出新的胜率结论。恢复静态定义有助于保留策略输入，但仍须核对名字、观察、未知处理及估值路径，不能只凭算法源码未改就认定全部行为等价。私有历史决策帧不随仓库作为测试夹具发布。

## 部署相关的分配契约

个人牌组 UUID、历史源码和运行时 manifest 不作为默认事实证明发布。通用策略目录不附带个人牌组推荐。Tullibint 策略仍识别其精确公开卡牌构成，并保留专用规划，不依赖个人 UUID。

已验证的公开捕获和 Veil 分配，需要在会话开始前通过 `configurePublicCaptureFacts()` 或 `configureVerifiedVeilFacts()` 显式注册，每个进程只注册一次。注册使用操作者核验过的源码/运行时摘要，以及精确公开构成和物理配置事实。参与者、profile、origin/前端、完整 36 张牌、增强和源码/运行时绑定检查继续保留。

本地事实缺失或不匹配时会拒绝使用该特殊契约，不会用合成的生产证明或宽泛服务器支持声明代替被移除的私有默认值。这些注册只是本地配置，不能证明某个公开服务器运行的就是参考代码。
