# 0.6.6 开局实验候选

这版新增三项 ToC 派生候选，用于分别观察首回合选屋和起手调度的影响。原有 89 个注册 ID 的决策路径保持不变，完整菜单增加至 92 项。默认 Engine V3、五项常用菜单和既有 0.6.5 Elo 数据保留原归属。新候选尚无完整对局胜率、Elo 或线上强度结论。

| 候选 ID                            | 首回合选屋修正 | 新调度估计                 |
| ---------------------------------- | -------------- | -------------------------- |
| `tactical-toc-opening-house-v1`    | 启用           | 不启用                     |
| `tactical-toc-opening-mulligan-v1` | 不启用         | 启用，需要完整公开实体牌表 |
| `tactical-toc-opening-v1`          | 启用           | 启用，需要完整公开实体牌表 |

三个候选在其他阶段均调用原 `tactical-toc-v2` 评分器，外层仍使用同一个循环保护与合法动作入口。首回合选屋候选不改变正常出牌排序，也不修改裁判允许的操作。

## 首回合选屋

旧选屋分把整手同势力卡牌的基础价值相加。先手只有一次普通手牌打出或弃置机会时，这会偏向数量多、但当下没有好牌可打的势力。

新候选只在完整可知的普通开局使用修正：先手自己的第 1 回合、空场、没有既有手牌操作或额外效果。它为实际提供的每个势力建立内部估值视图，复用公开可用性检查、ToC 单动作评分和共享手牌窗口分配，取当下能兑现的出牌或弃置机会。不能在空场打出的升级牌不会获得虚构出牌收益。

普通首回合手牌额度与卡牌授予的额外许可分别处理。已有短序列估计可以识别 Phase Shift 这样的公开额外出牌机会；复杂或未表示的开局条件回退旧策略。内部估值菜单不会作为动作发给裁判，最终只返回原真实菜单上的势力选择 ID。

一个复现起手含 Mars 的 Ammonia Clouds、Ironyx Propaganda、Destroy Them All!。旧策略因该势力累计 6.1 分而选 Mars，然后在空场打出评分 0.3 的 Destroy Them All!。其他势力有当前估值更高的合法单牌。新候选不再把 Mars 三张牌全算成本回合能做的工作。评分是内部启发式效用，不能解释为胜率，也不证明替代开局是全局最优。

## 调度需要完整的公开实体牌表

`Observation.players[you].deckList` 只包含卡名、定义、势力和数量，没有每张实体牌的增强序列。调度候选不会把缺失的增强当作零，也不读取隐藏牌序、游戏随机种子或对手私有手牌。

调用方可以通过构造参数提供完整的公开牌表。`physicalDetailsComplete: true` 表示该输入确实包含所有实体覆盖；没有覆盖的卡使用原始印刷默认值。`bonusIcons` 必须是**完整图标序列，含原生琥珀**，与普通公开牌表约定相同。

```js
import { createCodePolicy } from "./dist/src/ai/code-strategies.js";
import { openingDeckFromPublicList } from "./dist/src/ai/opening-deck.js";

// deck 是完整公开牌表，cards 是 36 个卡牌定义 ID，不是洗牌后的隐藏牌序。
const publicDeck = openingDeckFromPublicList({
  physicalDetailsComplete: true,
  cards: deck.cards,
  bonusIcons: deck.bonusIcons,
  bonusHouses: deck.bonusHouses,
  houseOverrides: deck.houseOverrides,
  skybeastHouses: deck.skybeastHouses,
});
const policy = createCodePolicy("tactical-toc-opening-v1", 42, {
  opening: { deck: publicDeck },
});
// 每次仍只传玩家 Observation，并执行其真实 legalActions 中返回的 ID。
const actionId = policy(observation);
```

构造器只复制公开实体属性，输出为排序后的无序多重集，不保留输入槽位顺序。重复卡牌的不同增强仍是不同实体。每次调度还会核对该表与当前公开 36 张聚合牌表一致，并逐张绑定实际可见起手的势力和图标。错误牌表、缺失牌表、未知卡牌、非标准开局、无法解释的估值或不完整观察都保留起手。

调度仅在整副 36 张牌都通过结构化估值检查时启用；任意一张牌产生未解析的效用值，整次调度比较就回退保留起手，不能只忽略该牌的未知部分。这里的策略估值覆盖与裁判的规则支持是不同范围。实际 seed 18 所用的公开牌组已成功绑定实体表，但尚不满足完整估值要求，因此调度候选保留起手，组合候选仅启用选屋修正。本次没有验证全部 500 副牌组的调度覆盖率，也没有把新候选接入正在运行的赛季。

现有普通 TCO CLI 不自动收集完整实体牌表。只在 CLI 选择调度候选而不提供上述 context 时，它会保留起手；组合候选的首回合选屋仍可独立生效。不能以聚合牌表替代完整输入来绕过这个边界。

## 调度比较如何计算

双方的调度都发生在全局第 1 回合，因此候选用 `you === firstPlayer` 区分先后手。先手估计第 1 回合的单张普通手牌窗口，后手估计第 2 回合的正常势力窗口。后手估计暂时保持当前可见空场，不假装预知先手会打什么。

对完整公开 36 张牌，按每个可选势力预计算单卡的公开效果、物质和等待价值。32 个确定的重抽样本共享这份先验，不为每个样本重复调用完整评分器。每次从**完整牌组**无放回抽取 `n−1` 张，因为原起手会洗回，原来的牌仍有机会重新抽到。固定采样使用独立的常量伪随机流，输入牌表先排序，不依赖引擎 RNG 或私有牌序。

当前手和每个重抽手都用相同的物质、等待折价与共享出牌窗口估计。少一张的成本通过较小的新手牌直接计入；相同品质的牌组不会因为重复抽牌而凭空获益。只有重抽平均效用减去两倍 Monte Carlo 标准误后仍超过保留效用，才选择调度。这个减项只是固定 32 次近似中的采样保守余量，**不是胜率区间，也不是经实战拟合的强度阈值**。

每次决策最多 `36 × 势力数` 次单卡先验估计，普通三势力牌组为 108 次，再做 32 个小型手牌分配。当前实现没有在每个普通回合运行这段采样。

### 已知限制

- 这是共享既有启发式估值的候选，未训练新的模型，也没有把先手胜率超过 50% 作为目标。
- 重抽估计使用独立单卡先验，不能完整表示所有手牌组合、后续场面和对手响应。它显式计算少一张的手牌效用损失，未完整模拟本回合结束时的未知补牌，因而可能偏向保留。
- 开局选屋复用了已有的有界短序列支持。复杂许可、组合实体、条件文本和未表示的开局会回退；这不是一个新的规则引擎。
- 知识中尚无对应的结构化效用时，调度不把未知值当成确定收益。完整物理牌表也不保证每张卡的战略价值都已被准确建模。
- 真正比较强度时应使用独立种子、交换策略席位与先后手，并分别比较选屋、调度及组合候选。新旧结果应保留各自源码和运行时身份，不能热改已冻结的赛季后混合 Elo。

## 验证范围

专项回归检查两席先手的具体起手、空场升级牌、Phase Shift 额外许可、后续回合与历史 ID 的委托行为、完整实体表绑定、好手保留与差手调度、少一张代价、牌表和手牌重排不变，以及不完整信息回退。另以已有冻结引擎验证真实起手的实际合法动作。它们属于功能与决策回归，不计入胜率样本。

新版本的最终测试数量和公开包边界结果记录在 `PUBLICATION.json`；0.6.5 的 636 项回归和 1,008 局 Elo 仍由[原校准报告](calibration-and-strategy-elo.md)说明。
