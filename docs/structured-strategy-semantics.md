# 0.6.0：结构化策略语义与对照测试

本版把代码策略对卡牌能力、当前选择步骤的判断迁移到结构化规则数据。保留原有 89 个策略 ID 和 5 项常用菜单，通过包版本和源码提交区分新旧实现；历史 Elo 继续绑定原冻结实现。卡文、解释标注和完整静态定义都保留。

## 本次改变了什么

### 当前决策由实际步骤描述

自有裁判补齐当前步骤的公开语义，独立 bot 消费同一合同。外服适配器能证明的语义也进入这个合同；它不读取对手隐藏区域，不用本地裁判替远端服务器结算。

| 决策 | 结构化依据 | 替代的文字依赖 |
| --- | --- | --- |
| 选择阵营 | 实际 option ID 与 `house`；需要估值续段时附加公开规则位置 | `Choose a house` 及按钮标签 |
| 选择效果分支 | `effect-choice` 的 `ability` 与 `path`，核对当前完整选项集合 | 同名提示或相同 label 匹配 |
| 选择卡牌续段 | `effect-selection`，或 `target-operation.selection` | `Choose cards` 和整张源卡摘要 |
| 预言翻面 | 物理槽位及逐选项的 `flip` / `keep` | 翻面提示、按钮文案 |
| Cauldron 下方牌 | 当前 `play-from-under`、精确来源及同一来源的公开 under-cards | `Cauldron:` 前缀 |
| 捕获目标 | `capture` / `captureOwn`、目标控制者和单次金额 | 泛化的 capture 关键词 |

公开规则位置只在当前步骤与当前观察者已可见的来源定义去掉显示标签后唯一匹配时生成。同构分支、隐藏来源、无法匹配的动态续段保持未知；不输出内部 frame、bindings、隐藏引用或 prophecy serial。选项的 house 现在真正进入观察，并补齐后续系列的 house 校验，合法动作集合及原有动作 ID 不因此扩张。

### 12 个摘要谓词迁移到规则特征

`semantic-features.ts` 读取 effect kind、operation、敌我受益方、选择绑定、触发时机和静态根字段，给出控琥珀、铸钥、获得资源、抽牌、归档、回收、场面控制、治疗、完全治疗、重置／使用十类潜在能力。分别处理 `play`、`use`、`any` 范围。

这修正了一个具体误判：旧紧急选屋分支只看到摘要里有 steal / capture，就可能把仅在收获或被消灭时发生的效果当作打出即能阻止对手铸钥。新版要求触发范围与当前用途一致，也保留条件性。没有当前目标语义时，不再从整张牌的摘要猜测这次是在治疗还是消灭。

未知公式、未覆盖机制和无法确定的受益方保持 `unknown`，不把未知牌视为已知无用。防守者授予攻击者的 `attackerBeforeFight` 目前明确保留未知；本版没有假装已完成它的全部估值。只缓存深度冻结且在检查边界内的定义，缓存资格和效果扫描都有 4,096 节点／32 层上限。

能力分类处理 40 种节点，既有数值估值接口仍有 47 个标签，完整静态库仍保存 267 种 effect kind。这些是不同口径；详见[卡牌知识](card-knowledge.md)，不能将类别识别数量当作完整规则模拟覆盖率。

### 原生兼容集中维护，特殊协议仍单独处理

`keyteki-native-semantics.ts` 集中普通菜单、按钮、捕获批次标题与已观察的日志模板。操作识别只看当前菜单，不把源卡名称拼进去搜索 destroy、purge、archive 等词。Hypnotic 在物理来源和当前模板都绑定后输出 `captureOwn` 与单次金额 1，分配总额度仍由独立证据证明。

选阵营优先使用 `house-select` 控件、按钮参数和 icon；界面标签改成中文或 `Done` 不改变实际选项。协议没有提供事件类型时，完整中英文消息模板仍要结合参与者、来源、连续新消息、唯一性、数值、资金池和物理目标验证。

外服的少量文本兼容继续存在，包括 Infurnace 的 Mine / Opponent's、导航步骤守卫、部分来源标题、管理员同意框和旧视图的阵营标签回退。模型输入和界面说明也继续保留卡文。本版移除的是代码策略用摘要或提示文案判断能力和规则步骤的做法，不宣称整个程序完全没有文字处理。

开发集完成 96 局，其中 96 局自然结束，技术终止 0 局、异常 0 局；主要估计纳入 24 个完整四局单位。

另外保留 4 局全旧控制（按版本标签归账 2:2）和修复前候选的 4 局试跑（1:3），均为自然终局、0 技术异常；它们不加入最终候选的 480 局。确认集第一次辅助启动包装器出现 Python 语法错误，尚未执行任何命令或开始对局；修正包装器后沿用相同设计与运行时，原退出 1 收据保留。


### 比较方法和适用范围

基线是冻结的 0.5.3（源码 `a14f6706e13c5dfbb43a481d796dcc17961f0f65`），候选是上述 0.6.0。两边在同一份自有规则引擎与同一公开观察合同上运行，比较 Engine V3 与 Card Effects V3 各自的新旧实现，不把两个不同策略直接混作版本对照。

使用此前测试集的 12 副真实牌组，覆盖 MM、DT、WoE、GR、PV、DM 六个系列，每系列两副。四局为一个比较单位：固定牌组配对和随机种子，遍历候选座位与先手的四种组合。开发集固定 96 局，确认集固定 384 局并使用不同种子；完整方案先于结果生成。开发与确认分开报告，不计入 2026-11-13 的 864 局历史 Elo。

一局发生技术异常，该四局单位整体不进入主要胜率，异常和所有自然局原始计数仍单列。区间按四局单位重采样，不把镜像局当作独立样本；合计仅报点估计。这里只有固定 12 副牌组和两个确认种子，区间表达这套测试内的波动，不认证所有牌组或真人环境下的普遍胜率。

开发集固定抽取每个单位的一局，给候选策略创建同 seed、同 ACK 历程的第二个实例，递归替换观察中的 `summary` 和 `label`，逐次核对动作 ID；实际对局始终使用原始观察产生的动作。确认集使用原始观察，不启用该额外探针。

公开证据见 [JSON 摘要](evidence/structured-semantics-2026-11-17.json)。账号、牌组个人标识、原始玩家视角和私有裁判不随报告发布。独立包的离线测试与实际线上运行均不依赖私有裁判；本次完整本地对照由维护者在独立规则项目上执行。

## 升级与当前运行安排

原有策略 ID 和配置字段继续适用；同一个 ID 在不同包版本中的实现可以不同。升级后重新构建，并为下一批运行冻结新运行时。既有已开始的 campaign 保留其原运行时和证据，不热改。

本轮没有发起外服或福州服在线对局，没有调用外部模型；国际服真人匹配继续暂停。外服兼容本次新增的是离线覆盖，后续服务器复验应另记实际源码与结果。
