# 准备阶段退役、聊天修复与福州自测

2026-11-17 起，本项目的维护测试以福州服和自有账号对局为主，国际服与其他玩家的公开匹配暂停。此前国际服适配、英文聊天和受控生命周期功能继续保留。

本页记录 **0.5.2** 的修复与验证，以及最后一个 **0.5.1** 国际服后台批次的实际结局。最终源码为 `2a47cc5f6415aad0cd3214d184095714940f1b09`；结构化计数与来源哈希见[证据 JSON](evidence/preparation-retirement-2026-11-17.json)。历史真人战绩不归到新修复版本。

## 本次修复

### 自建房选牌准备超时后的退役

原流程创建公开房间、锁定参与者之后，会等待双方牌组和房间身份满足复合就绪条件。等待超时产生 `HUMAN_DECK_NOT_READY` 后，旧版进入保留现场状态；既有的已绑定参与者准备房退役控制器只接入加入房间的入口；自建空房原有的 no-opponent 退出不覆盖锁定对手后的就绪超时。批次暂停能够阻止下一次匹配，但 worker 仍等待资源退役，因此可能长时间保留空闲宿主和浏览器。

新路径只处理该准备等待实际到期、启用了 `leaveAfterFinish` 的自建房。退出前重新核对同一原生连接与页面文档、房间和参与者身份、本人房主身份、从未开局且未请求 Start、没有待发或送达未知的命令、没有操作员暂停，以及策略宿主确实没有游戏 session。新鲜匿名完整大厅名册还必须证明本方确实在这间未开局的房间。

满足条件后只尝试一次普通 pending Leave，等待准确原生发送与清空确认，再取得独立全大厅离席证明，正常停止同一宿主并释放同一托管浏览器租约。Campaign 要等到 worker 的真实 exit 0，才完成归账。

| 准备证据 | 分类 | 之后的行为 |
| --- | --- | --- |
| 本方选牌命令和后续原生选中状态均匹配，对方尚未就绪或已离开 | `created-pending-departure` | 不计自然胜负；完整退役后可以按原预算继续 |
| 本方选牌状态不匹配，或无法确定复合超时原因 | `setup-failure-retired` | 不计自然胜负；完整退役后清 activeAttempt，但继续暂停批次 |
| 已经开局、请求过 Start、身份或连接变化、未知发送、操作员介入、原生证明缺失 | 保留未解决状态 | 停止新匹配，保留诊断证据 |

错误名本身不能证明对手没有选牌。新逻辑不会把旧历史 `HUMAN_DECK_NOT_READY` 直接改写成中性取消或自动恢复成功。

### HTTP polling 选牌观察

旧公开房间观察器在 WebSocket 路径会更新主选牌状态，但 polling POST 只交给旁路 tracker。仅使用 polling 时，已经真实发出的 `selectdeck` 可能没有更新主观察器，影响后续准备判断。

现在两种传输共用同一观察入口：POST 发送只观察一次，响应不会重放发出的命令，GET 仅观察入站；polling 向 WebSocket 升级仍保留原有连续性检查。没有为了补记状态再发送一次选牌。

### SPA 路由与真正文档切换

真实私房第一次在选牌确认处停止，但日志中存在准确的 `selectdeck` 和随后正确的选中状态。继续用生产 observer 复现后，发现 `page.framenavigated` 同时包含 SPA 同文档跳转和真正的新文档；原代码统一递增文档 epoch，导致同一原生连接后续的有效帧被丢弃。原现场没有导航事件日志，因此没有补造那次实际 epoch 跳变的证据。

现在使用共享的页面 CDP 文档观察器，在登录或首次导航之前完成初始化。同文档路由保留原连接与证据；真正的主文档 commit、同 URL reload、BFCache 恢复都使旧证据失效，iframe 不影响主文档身份。无法建立监控或监控意外关闭时停止准备。

初始化涵盖创建 CDP session、启用 Page 和获取 frame tree，整体受 `setupTimeoutMs` 限制；超时先立即拒绝 readiness，再清理 session。迟到创建或迟到返回不能恢复已失效的监控，也不会继续推进登录。自有私房测试直接复用这个生产 helper。

### 聊天空内容与回退来源

历史真人局曾出现一条只有两个双引号的模型回复。共享归一化现在过滤空引号和纯标点内容，同时保留正常的简短中英文、比分和完整 emoji，包括键帽 emoji。

普通事件没有有效回复时，该事件消费一次后静默跳过，不额外重试模型或重复发送。开场无有效内容时沿用现有中文／英文模板，并将来源正确标为 `template`。本次离线验证未调用付费模型，也未向真人发送聊天。

### 关闭聊天后的终局收尾

第二次完整私房虽然自然结束并自动离桌，但双方在 `social.enabled: false` 时仍各等待了 65,001 ms。原因是通用聊天排空逻辑一直等待根本不会建立的聊天 session。

现在只在正规化配置明确为布尔 `false` 时跳过这段等待，记录 `skipped / social-disabled`、等待预算和检查次数均为 0。这个回执不表示聊天已经排空或获得服务端回显；聊天开启或配置未知时继续使用原有有界等待。终局身份、操作员暂停、宿主静默、单次 Leave、原生离席证明与资源释放要求全部保留。

## 最后一个国际服后台批次

该批次运行的是 **0.5.1 / `365f06a`** 的 r5 冻结副本，原上限为 3 场自然局、5 次尝试和 2 小时新派发窗口。实际完成如下：

| 尝试 | 实际结果 | 计入自然战绩 | 收尾 |
| --- | --- | --- | --- |
| 第 1 次 | 1:3 自然负局，148／148 条命令确认 | 1 负 | 正常自动退役 |
| 第 2 次 | 无人入席 | 否 | 正常自动退役 |
| 第 3 次 | 无人入席 | 否 | 正常自动退役 |
| 第 4 次 | 无人入席 | 否 | 正常自动退役 |
| 第 5 次 | 准备超时，未取得已验证的完整游戏视角 | 否 | 保留原失败，之后人工释放资源 |

第 1 局有 333 份状态、148 个决策，148 次命令入队与 148 次效果确认一致。真实桌聊调用 5 次、接受 5 次，另从原生消息中确认 5 条本方英文回显，共 3,920 tokens。没有以入队标志代替独立的服务端回显。

第 5 次原错误为 `HUMAN_DECK_NOT_READY`，缺失的具体复合条件无法由历史错误名确定。2026-11-17 收尾时，两次新鲜匿名完整名册已证明原房间不存在、本方不在任何房间；认证页面也没有待准备或游戏中的 Leave 控件，因此实际 **0 次 Leave 点击、0 次 Concede**。

之后正常停止空闲宿主。旧 worker 按其原有 SIGTERM 语义保持暂停，确认服务端已离席且宿主已退出后，才对精确绑定的空闲 worker 强制停止；既有浏览器通过其托管租约正常释放。未新开浏览器或开始新对局。六个原运行进程均已退出，浏览器注册记录清除，账号 kernel lock 可取得，profile 与原始日志保留。

父进程记录的 driver 实际 exit 0，外层包装程序 exit 2，后者保留批次未自动完整通过的事实。独立复核完成后，在账号锁下显式清除旧 checkpoint 的 activeAttempt，追加 `operator-retired-unstarted-preparation` 人工收尾记录；原 5 条结果、预算和 health 未改。第 5 条仍是不可继续的 `operator-paused`，没有改写成自动退役成功。后续采集任务已经完成并停用，没有待执行的国际服任务。
