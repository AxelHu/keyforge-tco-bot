# 动态公式、公开场面与策略对照

版本：**0.6.1**。日期：**2026-11-17（Asia/Shanghai）**。

代码提交：`432abe7bf65a83b85297dbc1753c9ecf858b97c7`。完整脱敏结果见[逐局证据](evidence/contextual-formulas-2026-11-17.json)。本次只修改独立自动打牌包的策略理解和估值，沿用同一份自有规则核心；没有更换已部署的冻结运行时，也没有新增福州服或国际服线上对局。

## 这次解决的实际缺口

0.6.0 的能力分类器遇到对象形式的动态数量时，会标记 `dynamic:*`，并把“数量是否为正”判为 false。一部分控琥珀、抽牌等能力因此没有进入对应的策略加分或选屋判断。这是策略理解层的漏估，规则核心依然会执行牌的真实效果。

与此同时，旧动作估值器已经支持 `count`、`sourcePower`、`sourceAmber` 等若干公式。因此不能把静态库中 **804 张含公式定义的牌**说成全部失效。按相同的无场面静态扫描，旧版 any/play/use 范围中分别有 **245／147／78 张**带动态数量未知标记；这些数字既不是实战出现频次，也不是整卡估值为零的数量。

本版让数量求值和能力分类共同读取当前玩家可见的信息。动态结果不进入按静态卡牌定义保存的缓存；同一张牌在不同场面下可以得到不同数量。实现没有根据卡文里的关键词猜公式，也没有把裁判私有 frame、内部入场序号或未知对手手牌交给策略。

## 当前场面怎样进入计算

| 例子 | 原有路径 | 本版处理 |
| --- | --- | --- |
| Psychic Network、Yxili Marauder | 已经有一般 `count` 数值路径，动态能力标记及部分阶段处理仍有缺口。 | 用正确阶段的就绪 Mars 生物数量计算。Yxili 普通入场时耗竭，不能把手牌视图中的 ready 状态带入场上多算自己。 |
| Urien the Circumspect | `sourceArmor` 没有对应数量分支。 | 读取来源当前有效护甲，用于相应的获得／令对手失去琥珀数量。 |
| Imperial Forge | `creatureAmberTotal` 没有对应数量分支。 | 汇总己方符合条件生物储存的琥珀，计算减费，再检查实际可支付数量。 |
| Forging an Alliance、Free Markets | `distinctHouses` 未进入数量求值；同名限制字段不等于数量支持。 | 按规则筛选双方在场区域中的不同派系，应用上限；不擅自改成仅己方。 |
| 复制与来源数量 | `sourcePower` 等本来已有支持，但需要统一来源和阶段边界。 | 区分物理来源、复制规则提供者和候选目标。复制不会改换实体 ID，也不把对方伤害、计数器或外部增益直接拷进来源。 |

连续效果也必须读更新后的状态。例如，先返回两张生物到手牌，再随机清除其中一张，后续手牌数量应为 1；如果随机选择只产生获得琥珀的效果、并没有移动卡牌，两张牌的共同位置仍应保留，后续生物计数应为 2。

估值过程会跟踪明确的资源变化、区域移动、选择绑定、`lastAmount` 和 `withValue` 标量快照。来源从实际区域离开；巨大生物的两个组件分别计数；已知的准备、横置、眩晕和使用历史会影响后续筛选。一个目标组的数量仍在原来源上下文求值，不把每个候选目标替换成 source。

这些修正有的恢复遗漏收益，有的降低此前的过高估值。它们的目标是准确表达场面，不能仅凭增加了正向能力标志就认定胜率必然提高。

## 随机量先分别计算结果，再求期望

若偷取数量等概率为 1 或 9，对手池中只有 5，期望偷取量应为：

`0.5 × min(1, 5) + 0.5 × min(9, 5) = 3`

先把 1 和 9 平均成 5，再对资源池封顶，会错误得到 5。新的公开随机绑定路径最多枚举 32 个完整可见候选，在各分支内部处理数量、条件、循环和资源上限，随后平均效用。共同确定的状态可以继续使用；存在分歧的状态不被平均成一局必然发生的事实。随机铸钥及跨分支钥匙费用变化，不能仅凭平均池值认证成功。

求值结果区分 `exact`、`expected`、`interval`、`unknown`：有明确概率模型才给期望，只有上下界时不擅自取中点，也不把同一个随机绑定重复读取时的结果假定为独立抽样。`Value` 本身没有随机数字标签，随机来自具体 Effect。

公开手牌可以按已知样本计算既有单卡效用的期望；对手隐藏牌面没有被编造的牌种或奖励图标分布。Scrap、弃牌响应和未建模的跨区域续段可能改变后续取样，这些部分保留假设或明确的不确定性。效用期望不是经过校准的获胜概率。

## 还保留哪些未知

已支持公式按当前公开信息计算；缺失信息仍保留具体原因，例如：

- 现有 Observation 未提供完整的当回合友方／敌方被摧毁数，不能用当前弃牌堆数量替代。
- `drawnInDrawStep` 需要该抽牌步骤累计量。
- `eventAmount` 必须来自当前反应事件，不能借用相似提示里的 `pending.amount`。
- 某些绑定需要当前步骤的销毁、战斗或离区凭据；同一个可见物理 ID 不能证明它仍是旧绑定所指的那次入场。

公开手牌数量为 4 时，不带牌面筛选的数量可以是精确 4；其中 Mars 牌数在无牌面证据时只能保留范围，不能凭空估成 2。

**通用数量消费者目前只把 `exact` 送入确定性比较、循环和阈值。** 非精确结果会记录原因和不确定性，其数量槽仍以 0 表示这部分确定收益尚未计入。其他已知收益和结构上成立的条件潜力继续保留；随机期望通过专门的分支或线性效用路径参与排序。本版没有声称所有未知量都已变为精确值，也没有引入完整的本地规则模拟器。

分类器当前识别 **44 种效果节点**；类型接口含 **51 个标签**，静态库命中其中 50 种，另保留 217 种未进入该接口的静态节点。`50 + 217 = 267` 描述的是数据和类型范围，不是完整规则交互支持率。全部 2,546 份静态定义与原有卡文继续保留。

随后独立审查又证实三类依赖更新遗漏，最终候选 source03 一并修正：

1. 已知捕获量增加或减少后，依赖 captured 的力量必须重算，后续 `sourcePower` 不能读取旧值。
2. 已经在场的卡若捕获量变得不确定，其依赖力量也必须传递不确定性，不能仍给确定的旧力量。
3. Stratowise 的 Haunted 条件能力需要随连续弃牌与弃牌堆变化更新，不能沿用旧缓存。

窄复核还补上两条边界：捕获量变化可能使目标进入或退出光环范围，旧加成不能因目标已退出范围而继续成为确定值；抹字来源离场后，旧观察中已被抹去的牌面特征也不能被误当作当前完整特征。这些超出有界投影的持续修饰依赖保留具体不确定原因，不影响普通数量变化的精确计算。

前两候选已完成 **177＋672＝849 局**，全部与 source03 的 **672 局**分开；本轮共完成 **1521 局**。第一候选停止时可能有至多 2 场正在运行的对局，原运行器缺逐局启动账本，因此精确启动总数仍未知。source02 没有因比分提前停局，source03 也没有根据这些比分调权重。

## 固定对照设计

在任何新对局开始前，已经固定以下设计：12 副真实牌组，MM／DT／WoE／GR／PV／DM 六个系列各两副；比较 `tactical-style-engine-v3` 和 `tactical-card-effects-v3` 各自的新旧实现。

- 主比较对手是 0.6.0（`f827fce33cab297e57fd52500a4944b64b9097bc`）。开发集 96 局，确认集 384 局。
- 独立参照对手是 0.5.3（`a14f6706e13c5dfbb43a481d796dcc17961f0f65`），使用另外两组预先指定种子，192 局。
- 同一策略、牌组配对与种子下，新旧版本交换两个座位与两个先手值，组成四局单位。
- 只要某个单位存在缺局、非胜利终止或异常，主要估计排除整个单位；全部自然终局及排除原因仍单列。
- 两个工作进程，限制在 CPU 0、1，nice 10；每局最多 2,400 命令、180 回合、600 秒。

没有根据开发集比分改权重、挑选牌组或决定是否运行参照组。后续纠错沿用同一固定计划，已看过的旧候选前缀不会被描述成全新的未见样本；完整结果属于固定样本的重复比较。参照组使用自己的预定种子，三批结果分开解释。

开发集、确认集和独立参照集不合并成一个胜率。区间按各策略的完整四局单位重采样，是固定牌组及本批种子的条件性描述；牌组反复参与配对，且本次种子曾用于前一候选，不将其声称为完全未见留出验证。

对 0.6.0，两个策略的点估计都高于 50%，但至少一个条件性区间没有完全高于 50%；目前不能据此认定两种策略都获得稳定提升。

这项比较覆盖整组实现变化，没有单独移除某项修复作因果消融；因此不能证明上一轮少赢的 12 局就是动态 unknown 导致。

## 如何使用这些结果

这些对局在维护者自有规则环境中完成。公开包保留策略、静态规则知识、适配器和自动打牌机制，不捆绑完整裁判执行器；私人牌组身份、账号和原始观察也不发布。公开离线夹具可以直接运行，完整同样本比赛需要对应的独立裁判与牌组。

本轮没有重新评比 89 个注册策略，常用五项菜单与历史 Elo 表保持原有范围。历史的 0.6.0 结果及更早战绩保留在[结构化语义报告](structured-strategy-semantics.md)和[策略选单](strategy-guide.md)，不能把不同版本、不同种子和不同对手的胜率直接相减，当成单项修复的因果收益。

部署说明见[验证与兼容范围](validation.md)。国际服真人匹配仍暂停，本轮没有新的服务器适配验收或真人胜率结论。
